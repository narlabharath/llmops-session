# Sample Assignment Guidelines

> Synthetic document used for the LLM Ops teaching session.

## Assignment Objective

Weekly assignments reinforce the concepts introduced in live sessions. Each
assignment is designed to take 4–6 hours of focused work and produces an
artifact (notebook, short report, or code module) that the participant can
later use as a portfolio piece.

## Expected Deliverables

Every assignment specifies its deliverable explicitly. Typical deliverables
are one of:

- A completed Jupyter notebook with all cells executed
- A Python module passing the provided test suite
- A short written reflection (300–500 words) on a specific question
- A small dataset accompanied by a description of how it was produced

The assignment brief is authoritative; if the brief and these guidelines
ever appear to disagree, the brief wins.

## Submission Format

- Submissions are made through the learning platform's submission form
- Notebooks must be submitted as `.ipynb` files with outputs saved
- Code modules must include a `requirements.txt` if any non-standard
  packages are used
- File names must follow the convention: `lastname_firstname_assignmentNN.ext`

## Late Submission Handling

See the **Program Policy** document, section *Late Submission Policy*, for
the authoritative rules. In summary: 48 hours grace with note → 10% penalty
up to one week → not accepted thereafter except for emergencies raised
through support.

## Collaboration Rules

- Discussing concepts with peers is encouraged
- Sharing solution code or notebooks is **not permitted** unless the
  assignment brief explicitly says so
- Pair-programming on assignments requires both names on the submission
- Use of AI assistants is permitted **only where the brief explicitly allows**
  and must be disclosed in the submission

## Evaluation Rubric

Assignments are graded against four criteria, each contributing 25%:

| Criterion | What we look for |
|---|---|
| Correctness | The deliverable works as specified |
| Clarity | Code is readable; written work is well-organized |
| Reasoning | Decisions are explained where the brief asks for them |
| Completeness | All parts of the brief are addressed |

A participant who scores below 50% on an assignment is offered one
resubmission opportunity within seven days.

## Resubmission Policy

- One resubmission per assignment, only if the original score was below 50%
- Resubmission window: seven days from the date results are released
- The resubmitted score is capped at 75%
- Resubmissions must address the specific feedback given on the original

## Plagiarism Warning

Submitting work that is not your own — whether copied from a peer, a prior
cohort, a public solution, or generated by an AI assistant when the brief
forbids it — is treated as an academic integrity violation. See the
**Program Policy** for the consequences.
